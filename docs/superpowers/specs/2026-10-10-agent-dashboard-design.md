# AgentTouch 七日额度与任务看板设计

日期：2026-10-10。阶段：会话设计已确认，书面规格待审阅；尚未实现。

## 目标与已确认范围

用户希望在桌面设备上直接看到 Codex / Claude Code 七日剩余额度，以及正在进行和待阅读的任务数量。

- Codex 待阅读严格跟随桌面应用原生未读状态；在 Codex 阅读或手动改变未读状态后，设备同步变化。
- Codex 统计当前登录账号在侧栏中的本机、远程、云端主会话；排除归档、删除记录和子代理。按账号、执行主机、会话 ID 去重。
- 未读与运行状态是两个独立维度。运行中的会话也可能未读；未读不等于“已完成”。
- Claude Code 提供七日额度和运行中的主会话数量；本次不实现 Claude 待阅读，显示 `--`。
- 保留宠物表情和现有批准、听写、切席位等交互。新增信息覆盖 Claude / Codex 的全部六套皮肤。

## 现有证据与可行性边界

现有 `host/agentpet_host.py` 通过 hooks 与会话记录生成席位总体状态，`push_state()` 只推送各 agent 的状态；Claude 已有多会话条。固件在 `firmware/src/main.cpp` 解析消息，`face.h` / `face.cpp` 提供帧数据与绘制。

本机 Codex 桌面应用的代码使用 `electron-thread-read-state-v1` 保存按账号身份及执行主机隔离的原生未读集合；文件位于 `~/.codex/.codex-global-state.json`。已核对一个实际未读会话与保存集合一致。该格式是内部实现，不能视为稳定公共 API，也不能直接把文件中全部 ID 数量当成侧栏数量。

Codex 桌面连接包含 `thread/list`、`thread/status/changed` 与账号额度请求。当前会话的桌面 MCP 工具能返回跨主机状态，但这些工具不等于独立 Python host 可以调用的接口。独立 host 如何读取桌面已有连接的实时跨主机状态，是实现的第一个可行性关卡。

Claude Code 官方 statusline 数据提供 `rate_limits.seven_day.used_percentage` 与重置时间；账号或场景不支持时可能缺失。文档：https://code.claude.com/docs/en/statusline 。

## 方案选择

选择 Mac 后台统一汇总、设备只显示的方案，避免要求用户在每台远程主机安装额外服务。

另一方案是在每台主机部署采集器：运行状态容易获取，但安装维护成本高，云端也未必允许部署。仅使用本机 hooks 的方案无法满足全部远程和云端任务范围，因此不采用。

## 后台组件与数据流

新增独立适配模块，避免继续扩大现有 host 主文件；主文件负责调度与推送。

1. Codex 适配器：识别当前账号、当前配置的执行主机；取得完整非归档会话目录与各主机实时状态；只读采集原生未读并与目录交集。
2. Claude 适配器：复用现有会话 hooks，以主 session ID 聚合；使用 statusline 包装器采集额度，同时保留已有 statusLine 输出和配置语义。
3. 聚合器：生成额度、计数、任务行及完整性信息；各来源独立失败，不阻塞 BLE/TCP、批准或听写。
4. 传输与固件：后台经现有 JSON 行链路推送摘要；设备按需请求分页任务列表并显示。

### Codex 身份、目录与运行状态

必须按当前账号和当前主机配置选择数据，不合并旧账号、已删除主机或迁移遗留集合。目录遍历全部分页；不能仅统计最近 50 个会话。云端任务保留执行来源，避免同一云端会话被桌面投影重复计数。

运行数量仅包含明确处于运行状态的主会话。等待授权或用户输入单独标记“等你”，不计入运行数量；未加载会话不能直接判定为完成。连接状态、会话状态和原生未读分别存储。

优先复用桌面端可用的只读查询与通知入口。若公共接口不足，内部桌面桥接必须有版本检查且不修改应用包、不写回 Codex 状态、不复制凭据到日志。单独启动 app-server 不能被当成桌面进程真实运行状态的替代来源。

**可行性关卡：**先验证独立 host 能取得跨主机完整目录和实时运行状态，并证明不会启动、恢复或改变任务。若必须修改桌面应用或另行安装远程采集器才能取得数据，停止该部分实现并提交新的接入方案供用户选择；不得用估计值宣称已完成全量统计。

### 原生未读

读取原生状态只读文件或等价桌面只读入口，匹配当前身份和执行主机，再过滤非归档主会话。身份或主机映射不确定时显示未知；读取期间文件更新或 JSON 不完整时短暂重试，不覆盖最后有效快照。

在设备打开任务列表不会标记已读，也不维护另一份独立未读账本。任务行“在 Codex 打开”只导航到对应原生会话；是否变为已读由 Codex 自己决定。原生标记未读也必须反映到设备。

### 七日额度

剩余百分比 = `max(0, min(100, 100 - used_percentage))`。Codex 按窗口长度 10080 分钟选择七日额度，不固定假设 primary 或 secondary 一定是七日窗口；不混入其他产品桶。Claude 采用官方 seven_day 数据。无七日额度或 API 计费账号显示 `--`。

额度与任务快照独立刷新：额度每 5 分钟查询，额度通知到达时立即更新；任务使用状态通知，缺少通知时每 5 秒只读刷新。以快照时间识别过期，不依靠百分比变化判断新鲜度。

## 协议与兼容

保留现有 `state` 和 `sess` 消息，新增独立 `dashboard` 摘要及 `tasks` 请求/响应，版本为 1；旧端忽略未知类型，新固件未收到新摘要时隐藏看板。

摘要字段：`agent`、`generation`、`observed_at`、`quota`、`running`、`unread`、`waiting`、`coverage`。计数为整数或 null，null 表示未知，0 只表示完整读取后确认为零。

`quota` 包含 `remaining_pct`、`reset_at`、`observed_at`、`quality`；`coverage` 包含主机总数、可用数量及 `quality`（ok / partial / stale / unavailable）。各指标附独立质量，避免“运行数不可用”影响可用的原生未读。

任务请求包含 agent、筛选 running / unread、不透明 cursor 和 request_id；每页最多 4 行，响应包含 generation、next_cursor 和 complete。任务行包括后台生成的短句柄、标题、主机显示名、状态、未读。句柄只映射当前账号和快照，不在板子保存凭据或执行路径。

任务标题按 UTF-8 字符边界截断；发送前按实际接收缓冲区限制消息字节数，超限缩减标题或行数。具体字节上限由实现阶段核对现有各链路缓冲区后设为共享常量；不通过任意放大缓冲区掩盖消息问题。

## 设备界面和交互

- 左上角圆环：中间剩余百分比，下方“7日”；点击显示重置时间和更新时间。正常使用席位颜色，低于 20% 橙色、低于 10% 红色。
- 右上角显示“进行中 N / 未读 M”；Claude 未读位置显示 `--`。点击相应数量进入筛选后的分页列表。
- 列表每页最多四行，显示截断标题、主机及状态；点击行显示完整标题与“在 Codex 打开”按钮。返回回到宠物脸。
- 顶部布局为看板和既有 Claude 会话条预留不同区域；触摸区域不能重叠。批准、认领和麦克风等现有关键浮层优先，看板不抢按键或自动切换席位。
- 横放钟表、黄历、音乐等页面维持原有布局；新看板只出现在 Claude / Codex 脸页与主动打开的任务页。

首版不包含在设备回复任务、跨主机远程操作或批量标记已读。

## 失效、离线与安装行为

远程或云端状态读取失败时，可用部分显示为“进行中 ≥N”，并提示“部分状态不可用”；全部失败显示 `--`。若原生未读及目录仍完整，未读可以保持准确值；目录覆盖不全时未读也显示下界或未知，不能呈现为完整总数。

任务快照超过 30 秒未成功刷新标为过期，额度超过 15 分钟未成功刷新标为过期；过期值灰色并保留更新时间。设备与 host 断开后立即标记离线。重连请求完整新摘要与当前页，不拼接不同 generation 的任务行。

切换账号立即清除设备旧快照和任务句柄，重新加载身份匹配数据。格式版本不兼容时显示 `--` 并在本机设置页给出具体不可用原因，不写出账号凭据、对话正文或完整全局状态文件。

安装脚本须包含新增模块，保留现有 hook / notify / statusLine 的调用链。构建及验证通过后才更新已安装 host 和设备固件，并保留本次可回退产物。

## 验收标准

1. 对七日窗口选择、百分比边界、字段缺失和过期状态做适配器测试。
2. 对多账号、多主机、目录分页、子代理排除、归档删除、重复投影和原生未读交集做聚合测试。
3. 独立运行的 host 能观察本机、至少一个远程主机及云端样本；逐项与 Codex 桌面状态核对。没有可运行样本的来源明确标为未验收。
4. 在 Codex 阅读和标记未读、任务开始/完成/等授权、主机断开/重连后验证设备同步；直接打开设备列表不改变原生未读。
5. 断开任一来源后测试下界/未知与过期显示，确认不会误报零；切账号后不泄露旧快照。
6. 验证 BLE 与 TCP 的分页、UTF-8 长标题、重连和旧端兼容；列表数量不因页数受限。
7. 六套皮肤及 Claude 多会话条无遮挡；批准、听写、认领、其他席位和横放页面通过设备回归。
8. 运行现有 host 测试并构建 `amoled216` 固件；软件检查通过与真实设备验收分别记录。
